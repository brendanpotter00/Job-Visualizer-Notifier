## 0. The practical framing (do not lose this)

Until Phase 3 ships agent-authored scripts, the **only** custom companies that exist are
**ATS-client companies** (Greenhouse / Ashby / Lever / Gem / Workday / Eightfold). So
Phase 2's real, shippable job is: **make ATS custom companies graduate from UNVERIFIED to
VERIFIED and close jobs *safely*.** Build the oracle framework general enough that Phase 3's
`facet_sum` / `header` / `sitemap` oracles slot in without a rewrite, but for Phase 2 wire
only the two oracles the ATS clients can actually feed:

- **`declared_probed`** — the ATS API's own trusted, independent total, compared exactly
  (tolerance 0) against the post-dedup unique-id count. Used for the ATSs that return a
  *trustworthy* total: **Greenhouse** (`meta.total`) and **Workday** (`total`).
- **`self_consistent`** (BUILD-PLAN §3 self-consistency oracle) — for ATSs that publish no
  trustworthy total: **Ashby, Lever, Gem, Eightfold**. A run is complete iff it terminated
  cleanly (reached total / short last page / empty page, **not** a cap), pages advanced with
  disjoint id-sets, nothing errored, and the count is within the delta band of the
  trailing-run median; closing additionally requires a **3-consecutive-VERIFIED streak**.

Everything below is scoped to that. Amazon/Meta/YC `facet_sum` / sitemap oracles are Phase 3
— **plan the seams, do not build them.**

### 0.1 Non-negotiable invariants (carry from OVERVIEW/BUILD-PLAN)

1. **Only a VERIFIED run may close a job.** UNVERIFIED and FAILED never close.
2. **`tolerance_used > 0` on a run ⇒ that run closes nothing** (dormant in Phase 2 — no ATS
   oracle produces a tolerance > 0 — but wired for Phase 3 `facet_sum`).
3. **First VERIFIED run of a company, and the first run after any `script_version` change,
   close nothing** (a bad swap can then only *add* rows).
4. **A run that did not execute (FAILED) is not a miss.** Misses increment only inside a
   VERIFIED, close-eligible run.
5. **Fleet circuit breaker:** if > 20% of the night's custom runs FAILED, nobody closes.
6. **36h wall-clock floor** on `last_seen_at` (not the miss counter) before any close.
7. Never fake `first_seen_at` / `tracking_started_at`. No "generated by Claude" text.

### 1.1 `HarvestEvidence` — what the client observed beyond the row list

New module `src/backend/api/services/harvest_meta.py` (kept dependency-free — imported by
the ATS clients *and* by `harvest_verification.py`, so it must not import either, to avoid a
cycle):

```python
@dataclass(frozen=True)
class HarvestEvidence:
    """Completeness signals a client surfaces alongside its rows (feeds checks 1,5,6,9,11)."""
    declared_total: int | None      # trusted independent total; None if the ATS exposes none
    cap_hit: bool                   # pagination stopped on the client's safety ceiling
    terminated_cleanly: bool        # loop ended on reached-total / short page / empty page
    page_advance_ok: bool | None    # paginated: every page's id-set disjoint from the prior;
                                     #   None for single-shot ATSs (no pagination to check)
    pages_fetched: int = 1
    transport_ok: bool = True       # HTTP status in allowed set (check 1)

    @classmethod
    def single_shot(cls, declared_total: int | None) -> "HarvestEvidence":
        """Evidence for a one-GET ATS (Ashby/Lever/Gem, and Greenhouse's single page)."""
        return cls(declared_total=declared_total, cap_hit=False,
                   terminated_cleanly=True, page_advance_ok=None, pages_fetched=1)
```

#### 2.1 How each ATS total feeds check 9

- **`declared_probed`** (Greenhouse, Workday): `oracle_total = evidence.declared_total`. Pass
  iff `evidence.declared_total is not None` **and** `len(deduped) == declared_total` (exact,
  `tolerance_used=0`) **and** `not cap_hit` **and** `page_advance_ok is not False`. Any of:
  `cap_hit` (check 5), `len != declared` (check 7/10 — under=`count_mismatch`,
  over=`over_harvest`), `page_advance_ok is False` (check 6) → UNVERIFIED. **This is exactly
  where Target lands:** `declared_total=11960`, `len(deduped)=2000`, `cap_hit=True` → UNVERIFIED.
  A healthy Greenhouse board where `len==meta.total` and no cap → VERIFIED `reason='declared_exact'`.
- **`self_consistent`** (Ashby, Lever, Gem, Eightfold): no trusted total, so the "oracle" is
  the self-consistency conjunction: `terminated_cleanly and not cap_hit and
  (page_advance_ok is not False)` **and** check 12 (delta within band of the trailing median).
  `oracle_total = None`, `tolerance_used = 0`. Passing self-consistency makes the *run*
  VERIFIED, but **closing** additionally requires the 3-consecutive-VERIFIED streak (enforced
  in the leaf task, §2.4 Task D). Single-shot Ashby/Lever/Gem: `terminated_cleanly=True`,
  `page_advance_ok=None` (vacuously ok), so the run VERIFIES whenever the delta check passes.

#### 2.2 Zero-proof chain (check 11) — Phase-2 scope

A custom company is only ever created after an add-time probe returned `job_count > 0`
(`user_companies.py` add path), so a later 0-row harvest is suspicious. Route it thus:

- `declared_total == 0` **and** `evidence.transport_ok` (a trusted ATS declaring zero on a
  live 200) → VERIFIED `reason='zero_proven'`. **But it still closes nothing this run**,
  because the safety guard's `empty_scrape` rule (`jobs_seen=0 < 0.10*active`,
  `incremental.py:340`) trips and short-circuits the close — belt-and-suspenders, matching
  the 2026-03-29 lesson that a board→0 on a single run is indistinguishable from a scraper
  outage.
- `declared_total is None` (Ashby/Lever/Gem/Eightfold — **Marcus & Millichap is a Lever
  `200 []`**) → the zero cannot be proven from the ATS payload. The **canonical-backlink /
  brand-present** signals that *could* prove it are DOM/page checks that belong to
  Phase 3-4 (there is no page fetch here). So: UNVERIFIED `reason='zero_unproven'` → never
  closes. This is the M&M outcome: the design refuses to close 204 real jobs off a polished
  empty Lever board.
- `declared_total > 0` but 0 rows harvested → contradiction (declared says jobs exist, we got
  none) → FAILED (raise `HarvestGateError` from `run_gate` check 2/10): a transport/parse
  anomaly, retry.

### Task E — Fleet circuit breaker (§4.3)

**File:** `services/custom_companies_service.py` — add
`fleet_breaker_tripped(conn, *, window_hours: float = 24, min_sample: int = 5,
fail_fraction: float = 0.20) -> bool`.

Given the async fan-out (leaf tasks finish independently — there is no barrier where "the
night's companies" all complete together), compute the breaker as a **night-scoped aggregate
query**, read by each leaf task right before its close step (not at claim time — the claimer
runs *before* the fetches, so it cannot know this night's failures):

```sql
SELECT count(*) AS total,
       count(*) FILTER (WHERE success IS FALSE) AS failed
FROM scrape_runs
WHERE source_id LIKE 'custom:%' AND started_at >= (now() - make_interval(hours => %s))
```

Tripped iff `total >= min_sample AND failed::float / total > fail_fraction`. Global across
**all** custom companies on purpose (a systemic failure — a shared-client bug now, a
Browserbase outage in Phase 4 — is exactly the 2026-03-29 class this generalizes). It never
touches another user's *data* (source_id isolation holds); it only suppresses **this**
company's close. FAILED runs write `scrape_runs.success=False` (`fetch_custom_company.py:399`),
so the query is well-defined.

> **Note the started_at type:** `scrape_runs.started_at` is **Text** (ISO-8601 via
> `get_iso_timestamp`, `db_models.py:330`), so compare with `started_at >= %s` passing a
> Python-computed ISO cutoff string rather than `now() - interval` on the column. Lexicographic
> compare is correct for zero-padded ISO-8601 UTC. Pin this in a test with a boundary row.

**Tests:** covered in Task F's `test_fleet_breaker_suppresses_closes`.

## 4. Recommended Workday-cap fix (BUILD-PLAN §9, and the shipped-client memory)

The shipped `workday_client.py` **logs an ERROR and returns the partial 2,000, never raises**
(`:247-263`; confirmed against the `workday-client-2000-job-ceiling` memory). Phase 2's fix:

**Do NOT raise on cap-hit. Surface `cap_hit=True` and let the gate map it to UNVERIFIED.**
Rationale, decisive:
- **Raising ⇒ FAILED**, which (a) discards even the 2,000 rows we *did* get, (b) mislabels a
  legitimately-large board as a transport error, and (c) makes §8's regression impossible —
  §8 mandates **UNVERIFIED** + `guard_reason='unverified_harvest'`, not FAILED. A capped board
  is not a failure; it is an *incomplete but valid* harvest. UNVERIFIED is exactly the ladder
  state for "harvested rows but couldn't prove completeness."
- Surfacing `cap_hit` (via `fetch_jobs_with_meta`) + check 5 gives "never silently-partial":
  the user sees the 2,000 with an *unverified* badge and **nothing ever closes** — the
  OVERVIEW's intended outcome for Target.

**Do NOT paginate past 2,000 in Phase 2.** Raising `WORKDAY_MAX_PAGES` high enough to fully
harvest Target (≥598 pages) would also change the **public** Workday cron (shared client),
risk the 120s task timeout, and can only be validated at prod scale — mark any such raise
`PROD-VERIFY` and defer it. It is explicitly **not** what makes the regression pass; `cap_hit
→ UNVERIFIED` is.

**Reviewer note:** the `fetch_jobs` public delegator must preserve today's "return partial,
log ERROR" behavior for the six public crons; only `fetch_jobs_with_meta` (custom path)
additionally reports `cap_hit` so the gate can act on it.
